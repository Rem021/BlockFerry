# 架构与安全模型

## 技术选择

Windows 首发客户端采用：

- C# / .NET 10 LTS；
- WinUI 3 / Windows App SDK 当前稳定通道；
- beta.4 使用 `%LOCALAPPDATA%\BlockFerry` 下的受保护文件事务存储；SQLite 仍只是未来历史索引候选，不参与当前提交或恢复；
- 原始 Minecraft 文件保持原格式，不迁入私有数据库。

beta.4 的生产组合根只创建一套发现、内容和事务服务。`MainPage` 只投影 `MigrationWorkflowState`，不调用 `File`、`Directory`、环境变量、DPAPI、进程查询或目标写入 API。启动时必须先扫描认证事务记录；存在非终态时进入恢复优先页，在恢复完成前发现与新同步均被锁定。

WinUI 负责外壳、Mica、无障碍和 Composition 动画；同步核心不引用 UI，可在命令行与自动化测试中独立运行。根层优先使用 Mica，Acrylic 仅用于浮层或临时面板，避免每张嵌套卡片都实时模糊；减少透明度、高对比度或性能不足时必须降级为不透明材质。其他操作系统若进入正式路线，可复用核心并增加 Avalonia 外壳。

表现层使用一张占满可用窗口的连续 `version-canvas`：左侧编辑式版本文案、右下巨型版本数字和底部 `action-dock` 都是同一场景的分层内容，不建立来源/目标卡片、路线列表或外层主卡。巨型“20”只能是绝对定位、`aria-hidden`、不参与测量和命中测试的 Presentation 装饰层；真实版本仍来自 ViewModel，装饰层不得成为状态来源。底部只公开来源上下文、状态、运行时进度、详情和 CTA；当前原型状态视图只消费 idle/running/done 与四步进度并原位切换，Toast 不能成为完成状态的第二份来源。

主题属于 Presentation 本机状态：首次取系统深/浅偏好，用户通过单一太阳/月亮入口切换后持久化；主题值不得进入同步胶囊或跨设备玩家设置。顶栏、底部操作区与全宽迁移工作区可使用受控模糊，并必须提供减少动态、减少透明度、高对比度和不透明降级。迁移工作区将 Selecting、Reviewing、Executing/RollingBack 与 Succeeded 投影为互斥阶段，进度刷新只更新执行页的轻量字段，不重建选择或审核树。动画描述工作区入场、“20”揭示、按钮 hover/按下、阶段切换、同步进度、完成与主题切换；同步进度是唯一运行时循环动画，减少动态时必须停用。

顶栏和底部操作区属于无底座的场景覆盖层：不得绘制上下硬边或矩形面板，只能以方向渐变与蒙版让毛玻璃逐渐透明；减少透明度时使用同方向的不透明渐变，而不是恢复硬边。展示字与正文统一使用随程序分发的 Noto Sans SC，中英文字形一致；字体按 SIL OFL 1.1 分发并随包附带完整许可。

## 模块

```text
BlockFerry.App.WinUI
  ├─ Presentation / Motion / Accessibility
  └─ Application
       ├─ Discovery
       ├─ Planning
       ├─ Transactions
       └─ History
            ├─ BlockFerry.Core
            ├─ LauncherAdapters
            ├─ ContentAdapters
            └─ SyncProviders
```

- **Core**：实例身份、文件快照、语义文档、三方差异、同步计划和诊断；
- **LauncherAdapters**：发现启动器、实例根目录、实际 gameDir、导入状态与运行状态；
- **ContentAdapters**：解析 Vanilla options、FancyMenu 首启界面尺寸标记、Dark Mode Everywhere 1.x 当前模式、JEI 19.x 收藏与 Extreme Sound Muffler 3.x 静音规则；每次仍严格验证文件 schema，EMI 仅检测为不支持；
- **SyncProviders**：本机、本地胶囊、SMB、WebDAV 与未来云端；
- **Application**：编排恢复检查、发现、选择、计划、提交、恢复与撤销；
- **WinUI**：只呈现状态和收集明确的用户选择。

## 同步不是 Copy

每个内容适配器必须实现：

1. `Probe`：只读确认格式、版本与能力；
2. `Read`：转为带来源信息的语义模型；
3. `Plan`：比较基线、来源与目标，产出可解释动作；
4. `Stage`：只写事务暂存区；
5. `Verify`：从暂存或目标重新读取并断言后置条件；
6. `Commit`：原子替换；
7. `Rollback`：恢复快照并再次验证。

适配器不能在分析阶段写文件，也不能以“没有抛异常”作为成功。

## 事务状态机

```text
CheckingRecovery → Discovering → Selecting → Reviewing → Executing → Succeeded
        │                                      │              │
        └→ RecoveryRequired ←── RollingBack ←──┘              └→ Undo
                                      │                         │
                                      └──── verified terminal ──┘
```

硬门禁：

- 来源和目标必须解析到明确、不同的规范路径；
- 目标实例与相关 Java 进程必须关闭；
- 导入/下载文件必须稳定；
- 备份写入并校验成功后才能修改目标；
- 每个动作必须有预期结果、实际结果和恢复动作；
- 任一后置条件不满足时整笔事务失败并回滚；
- 相同来源状态再次执行不得产生新修改。

## 三方合并

双向或持续同步不能只比较来源与目标。BlockFerry 保存上次已同步基线：

- 来源 == 基线、目标变化：保留目标；
- 目标 == 基线、来源变化：应用来源；
- 双方相同变化：接受；
- 双方不同变化：冲突，交由策略或用户处理。

每个语义项目带稳定身份、格式版本、来源实例、设备、时间和内容哈希，避免依赖文件时间戳。

## 首次运行护盾

护盾维护一个受保护字段快照，而不是循环复制整文件：

1. 等待启动器导入结束且实例目录稳定；
2. 应用可预初始化的设置；
3. 记录首次启动前语义快照；
4. 监听目标游戏进程退出；
5. 重新读取并识别“首启生成”和“首启覆盖”；
6. 仅恢复用户字段，保留新版新增字段；
7. 验证后关闭护盾。

## 安全与隐私

- 账号目录、令牌、Cookie、密码、OAuth 缓存永远不进入适配器范围；
- `servers.dat`、截图、聊天日志和世界存档标记为隐私/大文件类别，默认关闭；
- 不从旧实例复制可执行 JAR、DLL、EXE 或启动脚本；
- 社区适配器未来必须声明只读/写入路径、能力和签名；
- NAS/云端胶囊使用内容加密与设备密钥，服务端不持有明文；
- 日志默认对用户名、服务器地址与绝对主目录做脱敏。

## 可测试性

每个适配器使用真实格式 fixture 覆盖：

- 新实例从未启动；
- 目标文件不存在、为空或只有新版字段；
- 双方同时修改；
- 文件名变化但内容身份一致；
- 一对多歧义；
- 处理中断与磁盘错误；
- 首次执行正确、第二次哈希不变；
- 回滚后所有目标文件与快照一致。

真实启动器验收必须在 Windows 虚拟机中进行，不能以纯单元测试替代。
